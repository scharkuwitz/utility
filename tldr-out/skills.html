A skill is a folder containing SKILL.md. Its description decides when Claude loads it; its location decides who gets it.

Key concepts Retain these.

01A skill is a folder with a SKILL.md file

SKILL.md holds YAML frontmatter (when to use the skill) and markdown instructions (what to do). The directory name, or frontmatter name, becomes the /command. Detailed material goes in supporting files that SKILL.md links to, so it loads only when needed.1,2
WhyA short SKILL.md keeps context cost low; reference files and scripts carry the detail.
  1. “Every skill needs a SKILL.md file with two parts” — Skills > Create your first skill
  2. “Keep SKILL.md under 500 lines. Move detailed reference material to separate files.” — Skills > Add supporting files

02The description is the trigger

Claude reads the description of each skill and uses it to decide whether to load the full skill. Put the key use case first and include words users would naturally say.1,2
WhyA vague description means the skill is not used automatically. Malformed YAML leaves the skill callable by /name but not matchable.
  1. “Claude uses this to decide when to apply the skill.” — Skills > Frontmatter reference
  2. “Check the description includes keywords users would naturally say” — Skills > Troubleshooting

03Location decides who gets the skill

Personal skills (~/.claude/skills/) apply to all your projects; project skills (.claude/skills/) apply to one repository and can be committed. Enterprise, nested, plugin and claude.ai account locations also exist. On a name clash, enterprise beats personal, and personal beats project.1,2
WhyCommit project skills to share them with the team; keep personal workflows in your home directory.
  1. “Where you save a skill decides which sessions load it.” — Skills > Choose where skills load
  2. “Enterprise over personal, and personal over project.” — Skills > Resolve skills that share a name

04You can control who invokes a skill

disable-model-invocation: true makes a skill manual only; use it for side effects such as deploy or commit. user-invocable: false makes it background knowledge that only Claude can invoke.1,2
WhyOtherwise Claude may start a workflow with side effects when it judges the moment suitable.
  1. “Claude can't invoke the skill on its own.” — Skills > Control who invokes a skill
  2. “Only Claude can invoke the skill.” — Skills > Control who invokes a skill

05Invoked skill content stays in context

Once invoked, the rendered content stays in the conversation as one message and is not re-read from disk. After compaction, only the first 5,000 tokens of each skill are kept.1,2,3
WhyEvery line has a recurring token cost. Write guidance that applies to the whole task and put the most important instructions first.
  1. “stays there across later turns” — Skills > Skill content lifecycle
  2. “keeping the first 5,000 tokens of each” — Skills > Skill content lifecycle
  3. “every line is a recurring token cost” — Skills > Types of skill content

06Dynamic context and forked subagents

A line such as !git diff HEAD` is replaced with the command output before Claude reads the skill. context: fork` runs the skill in a separate subagent that has no access to the conversation history.1,2
WhyInjected commands give Claude live data instead of guesses. Forked skills must be self-contained.
  1. “Claude Code runs the command and replaces the line with its output before Claude sees the skill content” — Skills > Create your first skill
  2. “The subagent doesn't see your conversation history, so the skill's instructions have to stand on their own.” — Skills > Run skills in a subagent

Exercises Hands-on practice.

01Create a skill that injects live context

Observe automatic loading and dynamic context injection in one skill.
  1. Run mkdir -p ~/.claude/skills/summarize-changes
  2. Save the content below as ~/.claude/skills/summarize-changes/SKILL.md
  3. In a git repository with uncommitted changes, ask Claude what changed. Then run /summarize-changes directly.
---
description: Summarizes uncommitted changes and flags anything risky. Use when the user asks what changed, wants a commit message, or asks to review their diff.
---

## Current changes

!`git diff HEAD`

## Instructions

Summarize the changes above in two or three bullet points, then list any risks you notice.
VerifyClaude summarizes your actual diff without you pasting it, in both cases.
VariationReplace the description with a vague one, such as 'helps with code', and test whether it still loads automatically.

02Make a skill manual only

Observe the effect of disable-model-invocation.
  1. Create .claude/skills/deploy/SKILL.md with a short description and disable-model-invocation: true
  2. Ask Claude in plain language to deploy
  3. Run /deploy staging
VerifyClaude does not run the skill on its own, but runs it when you type the command.
VariationChange the field to user-invocable: false and confirm the /deploy command is no longer available to you.

03Move detail into a supporting file

Practise keeping SKILL.md short.
  1. Add reference.md to the skill folder from exercise 1 with a list of risk categories
  2. In SKILL.md, add a line: For risk categories, see [reference.md](reference.md)
  3. Invoke the skill again
VerifyClaude's risk list reflects the categories in reference.md.
VariationRemove the link from SKILL.md and compare the result.

Common pitfalls

  • Frontmatter only counts when the opening --- is the first line of the file. Otherwise the markers become skill content.
  • Unrecognized frontmatter field names are ignored without an error. Match the field names exactly, hyphens included.
  • After compaction, only the start of a skill is kept. Re-invoke the skill, or move rules that must always hold into a hook.
  • An allowed-tools grant clears when you send your next message, although the skill content remains.

Review questions Answer first, then expand.

What does Claude use to decide whether to load a skill automatically?

The description frontmatter, plus when_to_use if set.

The same skill name exists in personal and project locations. Which runs?

The personal one.

How do you prevent Claude from running a deploy skill by itself?

Set disable-model-invocation: true.

Where should large reference material go?

In supporting files linked from SKILL.md, which should stay under 500 lines.

Why might Claude stop following a skill late in a session?

The content is not re-read each turn, and compaction keeps only the start. Re-invoke it or use a hook.

What does a skill with context: fork not see?

The conversation history.
